## Decisions Made

- **Use `git config --worktree gsd-beads.milestone` for milestone scoping** — mirrors the existing pattern in `hooks/worktree-post-checkout.sh:29` (`git config --worktree gsd-beads.dir`). Single git config knob per worktree; no new sentinel files.
- **Phase 4 STATE.md is intentionally minimal** — frontmatter (gsd_state_version, milestone) + a `**Current milestone:** vX.Y` line + a generated-by stamp. No bd reads. Phases 6-7 expand to include progress + decisions filtered by milestone.
- **`BEADS_ACTOR=seed` on every bd invocation in build-seed.sh** — ensures the dev's `git user.name` doesn't leak into the committed seed.jsonl. Pitfall 8 mitigation, baked in from the start.
- **Co-located src + wt-a + wt-b in milestone-scoping.test.mjs** — single tempdir with three siblings. One `rm -rf root` cleans up both worktrees and the source repo. Avoids orphan refs in `<source>/.git/worktrees/`.

## Issues Encountered

- **`bd-sync.sh` PostToolUse hook clobbered `.planning/REQUIREMENTS.md` and `.planning/ROADMAP.md`** during one early Bash-tool exploration of bd commands (probing `bd q`, `bd label add`, `bd close` directly via Bash tool). Per the warning in the executor prompt, restored those files via `git checkout HEAD -- .planning/REQUIREMENTS.md .planning/ROADMAP.md` before committing Task 1. Subsequent bd-touching operations were all wrapped in `bash <script>` invocations (build-seed.sh, seed-fixture.sh, seed-determinism.test.sh) so the hook fired only on the bash invocation (a non-`bd` command) and stayed quiet.
- **`bd q` with `--prefix sd` does NOT produce sequential IDs like `sd-1`** — it produces slug-style IDs like `sd-9x1`, `sd-ej8`, etc. (bd v1.0.3 internal slug generator). This is fine because build-seed.sh captures the ID into a shell variable (`P11=$(bd q ...)`) and uses that variable for subsequent `bd label add` / `bd close` calls. The plan task action correctly does this. The IDs are NOT stable across rebuilds (they depend on bd's slug RNG), but the JSONL exported from bd IS preserved byte-for-byte by `bd init --from-jsonl`, which is what powers the determinism contract.
